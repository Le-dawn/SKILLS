# 一致性资产：静态锚 + 动态追踪

用于需要“同一间屋、同一批物件”跨镜成立的短剧和长镜头较多的短视频。

核心区分：**识别特征与场景四图固定布局可以提前准备；人物和可移动物件“现在是什么状态”靠逐条动态追踪。** 把后者当成静态参考图去锁，是跨镜不一致的主要来源。

## 1. 静态锚（剧本定稿后可提前生成）

只包含三类，且只固定其**识别特征**，不固定全部细节：

| 类型 | 提前生成什么 | 不固定什么 |
| --- | --- | --- |
| 人物 | 三视图、关键服装与发型 | 每镜的姿态、表情、站位 |
| 标志性建筑／场景 | 能认出“就是这家店”的特征：门脸、招牌结构、标志性柜台或工作台的形制 | 墙面细节、货架摆件、地面杂物、光线角度 |
| 关键道具 | 决定剧情的物件身份：伞的花色与木柄、台灯的颜色与掉漆 | 它在每镜里的位置、开合、朝向 |

静态锚回答“是不是同一个东西”；它不回答“这一镜里它在哪、朝哪、开着还是合着”。后者全部进入动态追踪。

## 2. 逐生成片段循环：资产与视频交替

**同场景依赖动态状态的关键帧不能一次性批量生成；静态锚与空间基准可提前准备。** 先把整场甚至整集的关键帧全部出完，再统一跑视频，等于让每条关键帧各自重新想象一次房间和道具——这正是跨镜不一致的来源。

先完成[片段计划](segment-planning.md)。以下循环以一次生成片段为单位；一段内部可以有多个镜头，不在每次段内切镜处强制另生关键帧。需要上游实际状态的段按依赖推进：

1. **第一段**：结合已验收场景四图规划起始构图，结合静态锚（人物、标志场景特征、关键道具）和分镜起始状态生成关键帧 → 生成视频 → 验收。
2. **抽帧**：从这条采用片段里取代表帧、道具特写帧、与下一段衔接的实际采用区间末帧。
3. **更新账本**：记下位置、朝向、开合、数量、光位、服装细节、新增物件。
4. **下一段**：用账本里这条实拍帧派生关键帧（同机位直接裁切或推近；换朝向结合空间基准、实拍帧与静态锚做编辑），再生成、验收、抽帧。
5. **循环**到本场结束；下一场重新开始。

无上游动态状态依赖的片段可以提前准备；依赖上游实际状态的后续片段，在上游通过验收之前只做计划和草稿，不把未生成的关键帧列为已就绪素材。段内显式关键帧按选定模式及真实输入能力安排。

### 账本条目

每个场景一页，每条至少包含：

- 对象（人／道具／家具／光）
- 当前状态（位置、朝向、开合、数量、色温）
- 来源（片段版本 + 帧号）
- 最后确认（哪一镜验收时确认过）

动态状态以**最新采用片段**为准；固定布局须与场景四图一致。遇到固定物漂移先复核片段，不能把错误布局写入账本后当成新基准。

## 2.5 切点状态契约与出口留位

同一场里两条镜头之间的切点，不是“各自合格”就算通过。每个切点在生成前写一张契约，五项必须填满：

| 项 | 要写清 |
| --- | --- |
| 画内人物 | 切点前谁在画内、切点后谁在画内；谁消失、为什么 |
| 动作阶段 | 每个人在切点那一刻处于什么状态（还没入画／正走过来／站着／已坐下） |
| 道具状态 | 关键道具在谁手里、在哪、开合与朝向 |
| 机位关系 | 同一侧还是换轴；高度与景别怎么变；换轴后屏幕方向 |
| 声音 | 谁在说话，声音是否跨切点延续 |

**出口留位**：若下一镜的位置与动作依赖上一镜交代，应通过构图、既有空间建立、视线或声音让观众理解路径；不要求目的位置始终在上一镜画内。近景和反打允许人物、座位或通道在画外，但不得无依据改变物理位置。

**状态变化必须可解释**：关键交接和因果动作须可读，可在一镜完成、补过渡镜，或在切点处匹配动作阶段。非关键过程可有意省略或在画外完成，但须有足够视听依据。关键帧取变化前、中、后哪一阶段，由实际切点和分镜决定；不无故跳过关键动作，也不机械从头重演。

契约填不出来，说明切点还没设计好，不进入生成。

## 2.6 空间基准：同一场景四图一起用

默认每个用到的场景建立一套已验收四图。它们共同约束固定布局；生成该场景的每条视频任务（包括反打、续接、补拍）都必须把四图一起传入，不能只保存四图却实际挑一张。此规则替代原先强制 equirect、360 参考视频与 12 张方向关键帧的流程。

### 2.6.1 四图与方向

| 角色字段 | 图 | 要交代的空间信息 |
| --- | --- | --- |
| front | 正面图 | 以项目定义的正向看场景，标明拍摄位置和朝向 |
| back | 反向平视回望图（反向图） | 参考正面图，从相反方向平视回望同一空间，朝向相差 180°，拍摄位置须记录；不是水平翻转 |
| overhead_45 | 45°俯视斜角全景图 | 视线相对水平面向下约 45°，覆盖整体布局及主要物件高度；记录水平朝向 |
| top_90 | 90°垂直正俯视完整平面图 | 正上方向下观察完整平面布局、通道和位置；说明图上方对应的场景方向 |

“全景”指布局覆盖完整，不是 equirect 投影，不要求 2:1 或可旋转视频。四图共同使用同一场景坐标与固定物清单；前后图不是简单水平翻转。室内俯视可采用去顶／剖视表达，说明被隐藏的遮挡结构，不能把去顶效果带入成片。方向标记可记在素材清单中，不要求烘焙到参考图片里。

### 2.6.2 准备与验收

分镜完成后先明确场景范围、布局与四个视角，再严格按以下依赖链逐张生成：

| 步骤 | 本次生成 | 必须实际传入的前序图片 |
| --- | --- | --- |
| 1 | 正面图 front，建立场景基准 | 无本组前序图；依据已确认分镜与场景设定 |
| 2 | 反向平视回望图 back | 第1张正面图 |
| 3 | 同一场景的45°俯视斜角全景图 overhead_45 | 第1张正面图＋第2张反向图 |
| 4 | 同一场景的90°垂直正俯视完整平面图 top_90 | 第1张正面图＋第2张反向图＋第3张45°俯视图 |

每一步生成后先打开图片核对，再用通过检查的实际版本继续下一步。同一组不得并行生成后续视角，不得先出俯视图、仅引用正面图生成全部视角，或只在提示词里声称参考了前序图片。图像生成工具必须真实支持本步所需的多图参考输入；不支持时说明能力缺口，不退化为纯文生图冒充完成。

在既有素材清单或生成记录中保存每张图的角色、版本、完整提示词及实际参考文件路径／哈希。前序图更换时，按依赖链重做受影响的后续图并复核，不混用基于旧布局生成的下游版本。此处顺序规定的是四张静态图的生成过程；视频任务仍同时使用完整四图，images 的编号按实际输入顺序安排。

逐张检查后再四图对照：门窗、固定家具的数量、形制、物理关系、尺度和通道须一致，允许正常透视与遮挡变化。不一致先修素材，不让模型自行选择其中一张作为真相。

四图不固化人物站位、手持物、开合和剧情道具的当前状态，尽量使用无人物、无临时剧情物件的场景图。图中不可避免的动态细节须在提示词中明确由最新账本覆盖；固定布局漂移则不能仅更新账本就接受。

图片生成沿用当前环境可用能力与授权：内置图像生成，或用户／本地规则已授权的 ComfyUI MOSS／Qwen 路线；后者的生图工具与 API 模板需另行准备，见[执行适配](comfyui-h3.md)。MOSS 必须先加载 moss-image-prompt-enhancer，写 caption 草稿并编译；ComfyUI 生图占 GPU。产物归入 02_场景/，以场景ID和版本关联四图，素材清单记录角色、朝向、尺寸、哈希与验收结论。已提交四图不能原地替换。

### 2.6.3 每条生成任务的实际约束

- 新项目在 project.json 设置 require_scene_references=true，登记 scene_reference_sets；任务声明 scene_ids，并把对应四图全部列入有序 images。字段与示例见[执行适配](comfyui-h3.md)。已有项目新增／修订任务也必须声明 scene_ids，不能借旧项目兼容路径省略四图。
- 四图分别占四个图片输入；逐张写明实际 Picture 编号、方向和约束作用，明确四图为同一场景的互补视角、须联合遵循。具体 H3 格式仍由 batter-h3-prompt-writing 生成。
- 人物、关键道具、当前镜关键帧及续接尾帧另行安排。四图不替代动态账本或首帧 Guide；首帧也不替代四图。场景图只约束空间，不能让成片自动切成俯视、四宫格或依次展示四图。
- 当前 Ref2VA 合计最多 9 张图。先为每个场景预留四个槽位，再安排其他输入；多场景任务累计计算。超限时调整分镜或非场景素材方案，不能删场景图、拼四宫格冒充四个独立输入，或静默切到只收首尾帧的模式。
- plan/prepare/check/run 都检查四图关联、文件、实际图片绑定和引用编号；run 回执保存四图角色、哈希及编号。有效 API 中逐张核对 LoadImage → ref_images 连线，不能只看任务备注。

### 2.6.4 缺图、例外与历史任务

缺图、图间布局矛盾或图片额度不足时，保持 draft，修好后再 ready，不自动降为单图。确实无场景或用户明确允许例外时，记录具体原因与可追溯的授权依据到 scene_reference_exception；不能自行编造授权或把“省事／额度不够”当默认豁免。例外替代 scene_ids，实际保留的输入仍列在 images 并正常检查引用。

旧任务与恢复记录不批量迁移，未启用新契约的旧任务沿用原指纹；新修订使用新任务版本并采用四图契约。旧 360 工具、视频和底片保留供历史复现或显式专项需求，不是新任务四图的替代品。

### 2.6.5 生成后验收

对照四图与最新账本检查固定物的物理关系及当前状态，换机位允许正常透视、遮挡和屏幕位置变化。四图全部传入只证明输入完整，不证明模型利用或遵守了每张图；仍需实际看片，不通过时定位素材冲突、提示词、绑定或生成偏离。

### 2.6.6 续接与关键帧

同镜续接用上游实际采用版本在剪辑切点的末帧作首帧约束，同时保留四张场景参考。变景别可优先裁切实际帧维持道具状态；换朝向则结合四图布局与最新实拍状态重构关键帧。不能从一张图自由想象新空间，也不把四图当三维重建保证。依赖上游的关键帧仍逐段准备，不批量预生成。

## 3. 派生下一段关键帧的顺序

优先级从高到低，先选可追溯且便于核对“同一间屋、同一状态”的来源：

1. 同机位或小幅推近：直接用账本里最新的实拍帧作首帧；
2. 换轴／反打：不用上一镜帧直接当首帧（会把人物锁死在前一镜构图），而是以空间基准确定新朝向、以实拍帧延续动态状态，结合静态锚重新构图，并在提示词里写明必须延续的道具、位置与光；
3. 没有可用实拍帧时，从已验收空间基准结合静态锚建立关键帧，并记录状态依据；缺空间基准按 2.6.4 处置，不自由重建房间。

每张关键帧逐项验收：身份、物理位置（服务区／顾客区等）、视线对象、道具状态、画内人数。不合格重出，不带病进生成。

关键帧与提示词同源：按实际输入编号说明首帧作用，并核对真实锚定字段；起始状态与图一致，后续动作按分镜推进。具体格式由 batter-h3-prompt-writing 决定。

## 4. 一致性杠杆顺序

按代价从低到高：

1. **分镜**：根据叙事信息与表演负载选择长镜或切镜；只有轻微重构图时优先运镜，切镜应提供新信息。保持可理解的关系轴线，越轴时建立新的空间关系。
2. **首帧关键帧**：从账本派生，锁站位与当前状态。
3. **参考图与提示词**：场景四图 + 静态身份锚 + 物理锚点 + 明确的视线阶段。
4. **后期**：场级调色、颗粒、环境声床——只修光色，修不了几何和道具状态。

## 5. 合并长镜：消除切点的首选

相邻两段若同机位、同段对话、合计在当前工作流单次生成上限内，且表演负载与节奏合适，可合成一条重写：

- 收益：减少拼接接缝，但不保证生成段内部没有房间、光或道具漂移。
- 代价：牺牲景别变化；多句台词要按顺序排进一条提示词，时间要够。
- 记录：新片段用新版本号（如 `S08_v04`），旧的两段保留为历史版本。

## 6. 提示词反模式（实测）

| 现象 | 常见写法 | 改法 |
| --- | --- | --- |
| 让角色看画外，模型自行切广角去“展示” | “他看向门外的女儿” | 锁死机位，写“不移动、不揭示画外”，只让眼睛和头部小幅转动 |
| 台词被画成画面文字 | 对白较长、角色背面或白墙 | 强禁文字（衣服、墙面、道具都不许出现字），或改机位避开背面 |
| 程度词不生效（“半开”变全开） | half-open / slightly | 给绝对量：“不到一半”“约四十度”“全程保持折叠” |
| 道具自己走位 | 多个物件同框、手部动作多 | 给道具定坐标 + 近景手部构图，并在账本里记状态 |
| 无身份的白袖／陌生人入画 | 只写“对手在画外” | 点名对手身份与服装，“只允许这两个人” |
| 反打方位错 | 写“画面左／右” | 写物理锚点：柜台内侧／外侧、门口、工作台、货架 |

同一动作阶段给明确视线目标；需要转移视线时写明先后与触发。动作顺序及摘要（如该模式有摘要）与正文一致，格式按 batter-h3-prompt-writing 对应模式。

## 7. 生成前的提示词审查

一分钟的审查比十分钟的重生成便宜。逐镜问六件事：

1. 画内到底有谁、有没有无身份身体？
2. 每个人的物理位置？
3. 各阶段看谁、转向是否有依据？
4. 动作先后是否明确、是否与其他段落一致？
5. 道具状态是否与账本最新状态一致？
6. 有没有和本镜目标冲突的句子（例如一边要求走动一边要求精细交接）？

有条件时让独立审查代理只报“具体可改的句子”，不做泛泛评价；审查结果先修再提交。

## 8. 片段版本区分

- 每个片段版本独立 ID（`S08_v03`、`S08_v04`），独立输出目录、独立回执；旧版本不覆盖、不删除。
- 采用关系只写在选片清单里，每集可有多个版本清单（如 `剪辑选片_v02`、`剪辑选片_v21`），不靠“最新文件”推断。
- 维护一张片段版本表：镜／版本／请求时长／seed／输出帧数／状态／备注（弃用原因、被谁替代）。
- 账本每条状态都带来源版本号；上游换版后，依赖它的下游状态要重新确认。
