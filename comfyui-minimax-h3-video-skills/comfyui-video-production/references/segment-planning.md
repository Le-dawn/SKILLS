# 生成片段规划与落地

用于所有多次生成的作品、续接链和多段提示词审查。先加载 [batter-h3-prompt-writing](../../batter-h3-prompt-writing/SKILL.md)，再读其[长视频规划指南](../../batter-h3-prompt-writing/references/long-video-planning.md)；该指南是规划与提示词规则的主来源，本文件只说明怎样落入本制作流程。冲突时以 batter 版为主，不维护另一套分段算法。

## 从分镜到请求

先按故事节拍明确起因、可见／可听事件、结果与下一节拍的联系，再按对白试读、动作依赖、反应和换气分配时间。边界优先落在动作完成、完整台词、反应停顿或有依据的时空变化处，不机械按 15 秒切格，也不为了每段都闭环而重复收尾。

一个生成片段对应一次模型请求和一份完整提示词；可以包含多个连续视图（镜头），一个连续镜头也可以经多段生成拼接。分镜 ID、片段 ID、任务版本及提示词内 `[Shot N]` 分别映射。场次若已使用 C01 等编号，片段可用 G01 等未占用编号；沿用项目已有命名，不机械照搬 batter 示例的 C01。

当前执行器限制与帧数换算见[执行适配](comfyui-h3.md)。4–15 秒是当前请求约束，不是全片限制，也不是其他工作流的能力证明。按实际输入选择模式：只有文字、首帧、首尾帧、尾帧或多参考关系须真实成立。四图工作流继续按执行适配绑定，不能把四张普通参考在文字中宣称为真实首尾帧控制；需要的模式未获当前适配支持时记录技术缺口或提出可执行方案，不提交虚构模式。

## 计划表与状态记录

按项目规模在既有分镜中增加表格或登记独立计划，至少可查到：

| 项目 | 内容 |
| --- | --- |
| 标识与范围 | 片段 ID、对应场次／镜号／节拍、计划任务版本 |
| 叙事任务 | 本段要发生什么变化；段内镜头顺序、动作及完整对白 |
| 时长依据 | 试读或估时，动作与对白哪些串行／重叠，停顿及剪辑余量用途 |
| 双时间轴 | 全片预计区间；本段从零开始的切点；请求时长与预计采用区间 |
| 模式与输入 | 实际支持的模式、素材路径／版本、本次输入顺序与局部标签映射 |
| 入口／出口 | 站位、朝向、视线、持物手、开合、动作阶段、未完成声音等有关状态 |
| 交接方式 | 普通切镜、连续动作续接或明确时空变化；声音延续和剪辑方案 |
| 依赖与状态 | 已有素材、尚待上游选片／抽帧的素材、待解决问题；草稿与可提交分开 |

全局稳定信息沿用制作设定与素材清单；动态状态沿用本集账本，增加所需的持物手、动作阶段和声音状态即可，不重复建相互竞争的清单。每份提示词均须包含本段独立生成所需的身份、空间和当前状态；“同上”“继续上一段”不能替代真实输入和具体描述。全局角色／声线身份映射到各段局部 `(Sx)`，局部编号遵循 batter 版，不强求所有请求编号相同。

## 时长核算

规划时分别记请求秒数与预计源片时长；生成后用实测帧率和帧数得到源片时长 G。采用区间为左闭右开 `[in, out)`，K = out - in，要求 `0 <= in < out <= G`。按帧记录时 K = `(out_frame_exclusive - in_frame) / fps`；本流程真实末帧是 `out_frame_exclusive - 1`。

普通硬切的片长为各 K 之和；重叠转场减去每次重叠一次，新增定格或其他后期材料另计。被剪掉的头尾余量、重复交接帧不能重复计入。实际采用后重算全片时间；所有必需对白和因果动作必须保留在采用区间内。请求时长受节点帧数取整影响，不当成精确输出时长。

每份提示词重启局部 `[Shot 1]` 且首镜不带时间戳，后续切点用本段局部时间，严格递增并在段内。全片区间、剪辑入出点、任务 ID、计划表都放在 H3 正文字段之外。

## 从完整草稿到逐段执行

1. 可以先交付全片计划与每段完整提示词草稿。用户要求全套时逐份写齐，不用示例或“其余同上”替代；只要规划时不扩大成生成。
2. 缺少上游实拍帧或声音时，列清引用槽位与待确定事实，标记为暂定草稿。不能把规划图片当已有文件；这些任务保持现有 `draft` 状态，不发明新的执行器枚举。
3. 当前段素材齐备后，按实际输入顺序解析所有标签，包括场景四图、身份与动作参考；核对声音复制／参考关系及真实绑定。全局素材不必全部写入可见画面，隐藏道具不得提前泄露。
4. 按现有 `plan → prepare → check → run` 提交一段，保存回执和候选。段内有多个镜头时无需在每个切镜处停止执行或提前生成各镜关键帧；显式关键帧约束按真实工作流处理。
5. 选定实际采用区间后，检查段内切点及段间接缝，抽帧并更新实际出口。依赖该状态的下游再定稿与就绪。普通反打可用状态作构图参考，不强制继承前段尾帧构图。
6. 若上游实际结果违背必要故事事实，先修复或重做；不能通过更新账本把错误合理化。上游版本、裁切、出点或对白改变时，复核受影响的下游入口、引用、时长及台词覆盖，保留未受影响的工作。

## 跨段声音与验收

区分段内对白跨切镜和两次生成的声音拼接。`<scenetrans>` 不会使两个请求共享连续音频。跨段台词优先在完整句处切开；必须持续时记录可用连续音源／后期处理，实听检查音色、气口、口型和重复漏词。当前适配未绑定的参考音轨不能靠 `<Audio N>` 标签启用。

全片声音设计说明环境声、持续音效与音乐在哪里继续或结束。统一后期音乐与逐段生成配乐分开；重复相同音乐文字不等于波形连续，不给每个中间段自动添加淡入淡出或结尾重音。

进入生成前核对节拍和对白覆盖、负载、时间账、入口出口、引用解析与未解决依赖；进入交付前以实际片段检查这些项目，并完成[连续性与验收](continuity-and-review.md)。规划通过不等于成片通过，执行成功不等于内容验收。
