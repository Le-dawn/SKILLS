# ComfyUI 视频制作

把一个想法做成可执行、可追溯、可验收的视频；同一套方法也用于不生成时的检查、诊断与规划。生成类任务默认沿用当前 H3 完整二采工作流；题材、风格、片长、画幅、语言、角色数量由项目决定。真实项目的成功与失败只作为改进依据，不固化成某部片子的角色、地点、镜头数或台词模板。

## 先确定范围

先读[项目与素材约定](references/project-conventions.md)；所在工作区有 `AGENTS.md` 时同时读取其本地补充，没有时直接按本技能执行，无须复制原仓库规则。已有视频还须读取 `00_开始阅读.md`、`project.json`、`07_任务/jobs.json`、选片、运行回执与未解决反馈。从已完成的阶段继续，不重建或重投旧任务。只补问影响制作的缺失信息，已有授权和偏好继续有效。

**先定视频形态**

| 路径 | 判断依据 | 按需读取 |
| --- | --- | --- |
| 独立短视频 | 一条独立作品，以一个创意、知识点、展示目标或短事件为中心；可以包含多个镜头和生成片段 | [独立短视频](references/short-video.md) |
| 短剧 | 需要人物关系、对话调度、戏剧因果和连续状态；单集也走此路，多集再加跨集规划 | [短剧与连续剧](references/short-drama.md) |

按叙事复杂度选择，不按分钟数，也不把“单个短视频”误解为“只生成一次”。当独立短视频需要复杂对手戏时，补用短剧中的场面调度要求，无须扩展成整季。用户想做短剧但尚未选定故事时，从[短剧路径的创意探索与剧本选择](references/short-drama.md#0．创意探索与剧本选择)开始，通过口味探索、故事提案、偏好收敛、大纲与试写进入完整剧本；已有方向或授权直接写作时按需跳过。

**再定这次做哪类工作**

| 类型 | 可以做什么 | 产出 | GPU |
| --- | --- | --- | --- |
| 生成 | 从剧本到成片、单镜补拍、合并长镜、换版本重做、换画幅或时长重排 | 片段、成片 | 按授权提交 |
| 检查 | 剧本因果与时长、分镜粒度与桥、提示词六问、已有片段的切点与视线、成片规格、版本与记录 | 体检报告＋证据＋该修哪一层 | 不提交 |
| 修复 | 按检查结论局部重做、重剪、重渲染、补桥、补过渡 | 新版本，旧版保留 | 按授权提交 |
| 规划 | 创意探索、故事提案、大纲与试写、完整剧本、分镜、素材计划、关键帧计划、时长分配、镜头合并方案 | 故事／脚本／计划文件 | 不提交 |

检查类任务读[检查与诊断](references/audit-checklists.md)，按症状查层；只检查时声明不提交生成，结论不等于用户验收。

**按需读取**

- 先统一口径：读[术语表](references/glossary.md)，分清镜头、片段、版本、同一镜头的判定和锚定方式。
- 首次使用随附工作流：读[工作流说明](references/workflow-guide.md)，按用途选择执行 API 或源画布参考。
- 接入环境、建任务或生成前：读[ComfyUI/H3 执行适配](references/comfyui-h3.md)。
- 分镜到提示词转换、选片、续接、验收或问题诊断：读[连续性与验收](references/continuity-and-review.md)。
- 跨镜空间／道具一致性、场景四图、首帧关键帧、合并长镜或片段版本管理：读[一致性资产](references/consistency-assets.md)（空间基准见 2.6）。
- 集时长分配、剧本与分镜的时长换算、转场突兀诊断：读[时长与流畅度](references/duration-and-flow.md)。
- 正式 H3 提示词：**必须先加载 [batter-h3-prompt-writing](../batter-h3-prompt-writing/SKILL.md)，再写任何一条提示词**（包括补拍、重做、合并镜）。多段规划还须读取其 `references/long-video-planning.md`；本地缺失时先查找已安装副本，仍缺失则说明缺少的依赖，继续不依赖它的工作，不静默退回旧版或凭记忆套格式。迁移时一并携带该技能，不把本地增强版称为官方仓库版本。
- 已有专项创意技能时，可沿用其风格与创作方法；不重复启动另一套审批和任务清单。

## 规则优先级与多段规划

分段、时长预算、提示词模式与格式、引用映射及跨段连续性以 `batter-h3-prompt-writing` 为主；本技能正文与参考若有冲突，采用 batter 版并修正相应制作计划。其默认时长不代表后端能力：实际输入支持、帧数和参数边界仍须由执行适配确认。四图、二采、任务归档和内容验收负责将计划落实，不得用制作惯例强迫一个片段只包含一个镜头。

多次生成（无论成片长短）先完成[生成片段规划与落地](references/segment-planning.md)，再进入素材与任务阶段。可以一次写齐带依赖标记的提示词草稿；依赖上游实拍状态的任务只有在素材和边界状态核实后才 ready，不把“逐段生成”误解为不能提前规划整片。

## 制作顺序与阶段门槛

**内容与制作方向 → 完整剧本／视听脚本 → 分镜与生成片段计划（节拍、双时间轴、边界状态、输入映射）→ 静态锚 → 场景四图（按正面 → 反向平视回望 → 45°俯视斜角全景 → 90°垂直正俯视完整平面的依赖顺序生成）→ 逐生成片段循环（当前段素材与提示词 → 完整二采候选 → 选片验收 → 更新账本）→ 粗剪与验收 → 合成与交付。**

“完整”指足以解释作品内每个动作、对白和转场，不要求无对白演示也写文学长剧本。分镜前只确定人物关系、风格与制作方向；不提前批量锁定正式角色和道具图。剧本定稿后只提前生成“识别特征”类静态锚：人物、标志性建筑／场景特征、关键道具；场景的空间基准按固定依赖链生成：正面图 → 参考正面图生成反向平视回望图 → 参考前两张生成45°俯视斜角全景图 → 参考前三张生成90°垂直正俯视完整平面图。每步检查通过后再继续，同一组不得并行或先生成俯视图；前序图片必须作为实际图像参考传入，不以文字描述替代。四图共同约束固定布局；每条涉及该场景的生成任务默认四图全部输入，不自行挑一张。四图不锁人物与道具的当前状态；站位、朝向、开合与光位用动态追踪维护——**同一场景按片段依赖推进：先出上游片段、验收后按采用区间抽帧、把实际状态记进本集账本，再准备依赖它的下一段素材**，不把整场关键帧一次性批量出完（见[一致性资产](references/consistency-assets.md)）。已有合格素材可复用，先核对本次镜头需要。

每阶段产物规模随任务调整，已有合格产物直接沿用：

| 阶段 | 进入下一阶段所需证据 |
| --- | --- |
| 脚本（含提案与大纲） | 主题、动作因果、对白与收尾成立；人物年龄与时代背景、行业常识无硬伤；对白符合真实人类逻辑（无主谓颠倒的伪金句）；故事事件密度撑得起目标总时长（不把单幕短片注水成多集）；核心叙事道具已避开当前模型的高危交互盲区（如依赖手机屏幕小字、高频复杂进食等） |
| 分镜与片段计划 | 景别能看清关键事件；镜号与片段映射明确；各段叙事任务、表演预算、全片／局部时间、预计采用区间、边界状态、声音交接及素材依赖可核对 |
| 全局素材 | 静态身份锚及用到场景的四图已逐张、交叉检查，四图按固定顺序生成且有完整的累积参考记录；缺图或布局矛盾先修复，例外见一致性资产 2.6 |
| 当前段素材 | 本段所需身份、空间、道具状态及按需声线输入齐备，引用顺序明确；第一段从空间基准与静态锚建立起点，依赖上游的后续段从最新实际账本派生；不要求尚未生成的下游素材提前齐备 |
| 提示词与任务 | 每条提示词都在加载 `batter-h3-prompt-writing` 之后产出；没有改错说话对象、动作顺序或漏情节；每份可独立理解，局部标签与实际输入对应，未解决依赖仍为草稿；真实 API 图、素材和参数可预检 |
| 生成与选片 | 保存真实回执和源片；观察结果与设计要求分开记录；实际剪辑区间确定，抽帧更新账本后再准备依赖它的下一段 |
| 交付 | 内容观看、原声听审、相邻镜连播与文件检查有记录，未解决问题明确 |

这些是内容阶段，不是执行器 `status` 的新枚举。检查和规划可以从对应阶段开始、到对应阶段结束，不必走完整顺序；用户只要剧本、分镜、提示词或诊断时，完成该阶段即止，不自动扩为 GPU 提交。用户已授权某批次则按范围执行，不重复问权限；常规阶段检查不是新增用户审批点。

## 执行与记录约束

生成与修复类任务适用下列执行约束；只做检查时，保留“不覆盖旧产物、结论可追溯”两条即可。

- 默认直接运行**完整二采**；包含内部首段采样，不先单独一采验收再重跑二采。记录实际 seed 和全部输入，但不承诺同 seed、fixed 或二采放大后内容不变。
- 每部作品独立目录，素材和配置路径相对该目录；系列公共设定与单集输入分开。已提交素材、提示词、参数或工作流变动要新版本任务，不覆盖旧产物。
- 正式生成经随附 `scripts/comfy_submit.py` 执行器 `plan → prepare → check → run`；API 工作流与画布 JSON 区分。一次只提交本批次一条，成功下载后再下一条；失败停止，结果不明先查原任务，不盲目重投，不操作他人队列。
- 未经 `batter-h3-prompt-writing` 产出的提示词不得进入 GPU 批次；提交前按实际模式核对结构、参考标签与适用的说话人 ID：Ref2VA 六段，基础模式三字段，以该技能对应参考为准。
- 真正续接依赖**最终采用上游的实际剪辑末帧**及动作阶段；先上游选片，再准备下游。普通切镜／反打仍检查空间和叙事，但不机械复用前镜尾帧作新机位首帧。
- 音视频联合生成与输出音轨按当前工作流保留；参考音频／视频是否可用，取决于真实执行适配和当前任务设计，不能由文字标签虚构支持。场景默认完整输入四张图片，人物／道具参考和续接首帧不能替代它们；新项目启用 require_scene_references，新任务声明 scene_ids，实际绑定与例外契约见执行适配。可选参考视频只用于任务显式设计的额外需求，不替代四图。
- 执行成功、抽帧、ASR、正确字幕、完整解码都不能替代内容验收。无法观看或听审的项写明未完成；静态参考、提示词、生成片段、候选粗剪和通过验收的交付分别说明。

## 复用与后续调优

本技能在 `assets/workflows/` 内附完整二采 API 模板、清理过的源画布参考和来源哈希清单；在 `scripts/` 内维护提交器、抽帧工具及离线测试的唯一实现。复制整个技能目录即可携带这些文件，无须原仓库的 `tools/` 或 `AGENTS.md`；原仓库旧命令仅保留兼容入口。场景四图通过现有图片输入绑定，360° 视频不是默认步骤。迁移时仍须准备 `batter-h3-prompt-writing`、Python 3.10+、按需 ffmpeg/ffprobe、图像生成能力以及真实 ComfyUI 服务／节点／模型，见[执行适配](references/comfyui-h3.md)。不附带凭据、模型权重或单片硬编码脚本。

维护分工：`SKILL.md` 管入口、任务类型和共同约束；两条路径文件管创作流程；执行适配管真实工具能力；检查清单管逐项核对；验收参考管判定方法；项目与素材约定管可迁移的目录和归档规则。宿主 `AGENTS.md` 只补充本地要求，原仓库历史文档不是运行依赖。项目参数和故事事实只留项目目录。

调优采用“可观察失败 → 定位发生环节 → 小范围修订 → 同类用例复核”。仅把跨题材可复用的结论更新到相关参考，不把个案审美、推测原因或一次成功写成全局定律；技术换参、换模式的 GPU 验证仍服从当前授权范围。
